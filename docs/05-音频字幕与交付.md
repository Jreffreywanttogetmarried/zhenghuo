# 05 · 音频、字幕与交付

## 1. 默认：无配音，字幕即旁白

教程里的四条样片都是 **全片无配音，字幕就是旁白**。好处：

- 制作快，不用找配音/对口型；
- 字幕准确，不会出现 AI 配音读错数字；
- 观众静音刷也能看懂；
- 后期在平台 App 里配一首纯音乐即可。

**重要**：无声预览不是成片。交付时必须说清楚「有音轨 / 无音轨」，不要把无声渲染描述成已经配音配乐。

## 2. 字幕工作流

1. 在分镜表里按每秒 6–7 个字写；
2. 同步写进 `episode.json` 的 `subtitles`；
3. 运行检查：
   ```bash
   python tools/check_episode.py episodes/<slug>
   ```
   会检查重叠、超时长、速度、字数；
4. 导出 SRT 备份：
   ```bash
   python tools/export_srt.py episodes/<slug>
   python tools/export_srt.py episodes/<slug> --max-chars 18
   ```
5. 需要纯文本旁白（给 TTS 或配音）：
   ```bash
   python tools/export_srt.py episodes/<slug> --txt
   ```

### 字幕格式

- 普通字幕 64px，白色，字间距 2px，最多两行；
- 关键词用 `【】` 包住，渲染为金色 `#FFC15E`；
- 单句 2–3 秒；14 个字约 2.2 秒；
- 主体在下方时，字幕用 `"position": "top"`（top=110）。

### 可选的 TTS

如果以后要配音，可以用 `edge-tts` 生成中文旁白，再把音频传给渲染器：

```bash
python -m pip install edge-tts
edge-tts --voice zh-CN-YunxiNeural --text "旁白文本" --write-media narration.mp3
python tools/render_video.py episodes/<slug> --audio narration.mp3
```

- TTS 生成后必须人工听一遍：数字、专有名词、断句很容易错。
- 有配音时，字幕可以保留（推荐），但要确保字幕和语音同步。
- 不要用未经授权的真人声音克隆。

## 3. 音乐与音效

- 教程建议：发抖音时在 App 里选一首节奏感强的纯音乐。
- 如果要在本地混音：
  - 音乐音量压低到人声以下约 −8 至 −11 dB；
  - 整体响度约 −14 LUFS；
  - 结尾留 0.5–1 秒淡出；
  - 不要用版权不明的音乐。
- 重要节点可以加音效：数字落定、镜头穿过、图表生长。但不要每 2 秒一个音效。
- 音乐节拍可以和动画对齐（例如 112 BPM，每拍约 16 帧 @30fps），但不要为了卡点牺牲叙事。

### 只加 BGM + 卡点（无配音）

这是最简的一条音频路线，适合暂时不做配音的期数：

1. 先选音乐，确定 BPM 和第一拍偏移；
2. 在 `episode.json` 写 `audio`：
   ```json
   "audio": {
     "src": "assets/audio/bgm/bgm.mp3",
     "bpm": 120,
     "offset": 0,
     "loop": true,
     "volume": 0.85,
     "fadeOut": 1.5
   }
   ```
3. 用 `python tools/beat_grid.py --bpm 120 --offset 0 --duration <秒> --every 8` 生成拍点表；
4. 把场景切点放在 4/8/16 拍的整数倍上；
5. 场景里用 `env.beat.pulse(env.globalT)` 做节拍脉冲；
6. 渲染时会自动挂 BGM、循环、音量和片尾淡出。

> 卡点只卡 BGM 时，音乐必须先定死。换歌会导致所有卡点错位。

## 4. 渲染时加音轨

方式一：把音频写进 `episode.json`，渲染时自动读取：

```json
"audio": {
  "src": "assets/audio/bgm/bgm.mp3",
  "loop": true,
  "volume": 0.85,
  "fadeOut": 1.5
}
```

```bash
python tools/render_video.py episodes/<slug>
```

方式二：命令行临时指定：

```bash
python tools/render_video.py episodes/<slug> \
  --audio assets/audio/<slug>.mp3 \
  --audio-loop \
  --audio-volume 0.85 \
  --audio-fade-out 1.5 \
  --output episodes/<slug>/output/<slug>-with-audio.mp4
```

- 渲染器默认会 `apad` 补静音/裁切到视频时长；
- `--audio-loop` 会先把音频循环到视频长度；
- 输出 AAC 192kbps；
- 没有音轨时，成片就是无声视频。

## 5. 交付包

每期发布包至少包含：

| 文件 | 说明 |
|---|---|
| `output/<slug>.mp4` | 成片，1920×1080 / 30fps / H.264 / yuv420p |
| `output/<slug>.srt` | 字幕备份 |
| `output/stills/` | 关键帧截图（至少首帧、中段、尾帧） |
| `sources.md` | 事实与素材来源 |
| `notes.md` | 制作笔记、风格编号、修改记录 |
| 封面 | 单独导出 1920×1080 或平台尺寸 |
| 发布包 | `templates/发布包.md` 填好的标题/简介/标签 |

## 6. 命名规范

```
episodes/<slug>/
  index.html
  episode.json
  outline.md
  storyboard.md
  sources.md
  notes.md
  scenes/
    01-hook.js
    02-world.js
    03-mechanism.js
    04-story.js
    05-payoff.js
  output/
    <slug>.mp4
    <slug>.srt
    sample-15s.mp4
    stills/
      <slug>_000p000s.png
```

- slug 用英文/数字/短横线，例如 `001-sky-blue`、`002-tulip-bubble`。
- 不要用中文文件名做 slug；中文放在 `title` 字段。
- 分段渲染的文件用 `part1.mp4`、`part2.mp4`，拼接后再改名。

## 7. 平台规格

| 平台 | 建议 |
|---|---|
| 抖音 / 视频号 | 默认横屏 1920×1080；竖屏版本需重新排 layout（1080×1920），不要直接裁 |
| B 站 | 1920×1080，30fps，H.264；简介里放时间轴和来源 |
| YouTube | 1920×1080，30fps；可另导 4K 版本（渲染时改 width/height） |
| 小红书 | 竖屏更常见；同样需要独立 layout |

## 8. 发布前技术检查

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,pix_fmt \
  -show_entries format=duration,bit_rate -of default=noprint_wrappers=1 episodes/<slug>/output/<slug>.mp4
```

确认：

- [ ] `codec_name=h264`
- [ ] `width=1920` `height=1080`
- [ ] `r_frame_rate=30/1`
- [ ] `pix_fmt=yuv420p`
- [ ] `duration` 与分镜表一致
- [ ] 有音频时存在 `aac` 流
- [ ] 文件能正常播放到最后一帧

## 9. 发布文案与声明

- 简介里写：数据来源、音乐、图片/字体许可、AI 生成内容声明（如适用）。
- 真实人物照片：角落标注来源；找不到授权就用剪影。
- 投资/健康类：加一句「本视频为科普，不构成投资/医疗建议」。
- 不要把「据说」写成事实；评论区被质疑时，能直接贴出来源。
